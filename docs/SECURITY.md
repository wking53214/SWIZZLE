# Security

## What SWIZZLE does that needs care

It generates repositories, writes them to disk, and runs two kinds of code it
did not write: the target under test, and the generated repository's own test
suite (which the target executes as part of its work).

## What is guaranteed

**Every case runs in a disposable directory.** `Sandbox` owns one directory
under the system temporary area, created by `mkdtemp`, and deletes it on the
way out.

**Writes go through a check.** `Sandbox.resolve()` refuses a path that leaves
the sandbox lexically (`..`, absolute) and refuses one whose parent *resolves*
outside it — which catches a symlink already on disk that the lexical check
cannot see.

**Deletion re-checks.** `dispose()` refuses to delete a directory whose name
does not carry the sandbox prefix, and refuses to delete a directory the
sandbox did not create.

**Every subprocess has a timeout**, a working directory inside the sandbox
(checked), and is killed on the way out.

**The user's repositories are never the subject.** A case is always a
generated world. SWIZZLE never points a target at a directory the user
supplied.

## What is NOT guaranteed

**This is not an OS-level jail.** A target invoked inside a sandbox is an
ordinary subprocess with the ambient permissions of the user running SWIZZLE.
If it decides to write to the home directory, nothing here stops it.

The isolation is over the **input** — what the target is pointed at, and what
SWIZZLE itself will touch — not over the target's syscalls.

That distinction is deliberate and it is load-bearing. A case in this
repository can make a target follow a symlink out of the case directory, and
the scope oracle's job is to notice when it did. Hiding that behind a jail
would remove the signal the experiment exists to collect. So the sandbox makes
escape **visible** rather than impossible, and stages the bait inside the
sandbox where a real file can be harmed without harming anything of the
user's.

If you are running SWIZZLE against a target you do not trust, run it in a
container. The framework will behave the same and the blast radius will be the
container.

## Code execution, in detail

Three things execute:

1. **The target.** Whatever binary or module the adapter invokes.
2. **The generated repository's test suite.** The target runs it; SWIZZLE also
   runs it once afterwards to ask whether the repository still works. Both
   suites are generated by SWIZZLE from a genome. They contain arithmetic
   assertions and, for temporal and crash cases, a test that edits a file in
   its own repository or signals its parent process.
3. **Nothing else.**

## The kill guard

The crash-consistency mutator makes the generated suite send `SIGKILL` to its
parent — which is the target, mid-run, at a point the target chose.

SWIZZLE also runs that same suite afterwards, and at that moment the parent is
**SWIZZLE**. The first version of this case killed the harness instead of the
target: silently, exit status 0, no output, which is the worst possible way for
an evaluator to fail.

The guard is an environment variable (`SWIZZLE_NO_KILL`) that the harness sets
around its own invocations and that the generated test checks before
signalling anything. If you add a mutator that does anything to a process,
respect it.

## Trust and the target

The Ghost adapter sets `GHOST_TOOLS_TRUST=-`, which is that target's own
documented switch for a harness scanning its own fixtures. It is set
explicitly, in one place, in the adapter, and the target prints a receipt line
saying it was used. It is not set globally and it does not affect anything
outside the sandbox.

## Stray sandboxes

A crashed run can leave one behind. `swizzle sandboxes` lists them and
`swizzle sandboxes --purge` removes them, keying on the prefix so it cannot
touch anything else in the temporary directory.

## Reporting

If you find a way to make SWIZZLE write outside its sandbox, that is a bug in
SWIZZLE rather than a finding about a target, and it should be fixed before
the next run. `Tests/test_lab_sandbox.py` is where the guarantees above are
asserted.
